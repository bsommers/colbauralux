# Build and Deploy

Omega Ratrace plays straight from source with no build step. The build exists to produce a minified bundle, a single self-contained HTML file, and a GitHub Pages site.

## Requirements

- Node.js 22 or newer. Nothing else is needed to run the game, tests or tools.
- For the minified build, `esbuild` on the PATH or available through `npx`. Without it, the build falls back to an unbundled copy of `src/` and prints `UNBUNDLED fallback`.
- For screenshots and the smoke test: a Chrome or Chromium that `tools/shot.mjs` can find (`--chrome <path>` overrides it).

No packages are installed by the project. `package.json` has no dependencies.

## Commands

| Command | What it does |
|---|---|
| `npm start` | Serves the repo over HTTP on port 4796, or `$PORT` (`node tools/serve.mjs [port]` defaults to 4781). |
| `npm test` | Runs every `test/*.test.mjs` suite with `node --test`. |
| `npm run lint:imports` | Checks every import in `src/` resolves and is exported. |
| `npm run build` | Runs `node tools/build-web.mjs` and writes `dist/`. |
| `npm run plan` / `npm run tracker` | Swarm tracker (development only). |

## What the build writes

`node tools/build-web.mjs` writes into `dist/` (gitignored):

| Output | Contents |
|---|---|
| `dist/web/index.html` | The page, pointing at the bundled script. |
| `dist/web/app.js` | The game, bundled and minified with esbuild, ES module format. |
| `dist/web/style.css` | The page stylesheet, minified. |
| `dist/omega-ratrace.html` | One self-contained file with JS and CSS inlined. Opens from `file://`. |

Measured with esbuild on this repo (sizes from the build log, gzip in brackets):

- `app.js` 84.7 KB (32.3 KB)
- `omega-ratrace.html` 86.8 KB (33.3 KB)

The build log prints the live numbers every time you run it, so treat those as a snapshot rather than a promise.

When the build runs in the unbundled fallback, it removes any old `dist/omega-ratrace.html` rather than leave a stale copy.

## Checking a build

1. `npm test` passes.
2. `npm run lint:imports` reports 0 errors.
3. Open `dist/omega-ratrace.html` in a browser, or run `sh tools/smoke_web.sh`, which loads the shipped single file headless with `tools/shot.mjs --strict` (fails on any console error) and checks that the frame is not blank.

## GitHub Pages

`.github/workflows/pages.yml` runs on pushes to `main` and on manual dispatch:

1. `npm test`.
2. `node tools/build-web.mjs`.
3. Assemble `_site/`:
   - `docs/site/` at the site root (the landing page and images),
   - `dist/web/` at `/play/` (the playable game),
   - `dist/omega-ratrace.html` at `/omega-ratrace.html` (the single-file build).
4. Upload `_site/` as the Pages artifact and deploy it.

To enable it, set the repository's Pages source to "GitHub Actions" once in the repository settings.

## Local Pages preview

Build, then serve the assembled site the same way CI does:

```sh
node tools/build-web.mjs
rm -rf /datanapps/pages-preview && mkdir -p /datanapps/pages-preview/play
cp -r docs/site/. /datanapps/pages-preview/
cp -r dist/web/. /datanapps/pages-preview/play/
cp dist/omega-ratrace.html /datanapps/pages-preview/
python3 -m http.server 8080 --directory /datanapps/pages-preview
```

Then open http://localhost:8080/ and http://localhost:8080/play/.

Keep large build output off `/tmp`; the preview above writes to `/datanapps`.

## Troubleshooting

- **`UNBUNDLED fallback` in the build log.** esbuild was not found. Install it globally or run the build where `npx esbuild` works. The fallback still runs, but it is not minified.
- **`dist/web/` does not load from `file://`.** Browsers block ES module scripts from file URLs. Use `dist/omega-ratrace.html` for file-based play, or serve over HTTP (`npm start` serves the source tree, not `dist/`).
- **Pages deploy fails at configure.** The repository's Pages source is not set to GitHub Actions.

## Releases

Pushing a tag `v*` runs `.github/workflows/release.yml`: it runs `npm test`, builds, smoke-tests the single file, and creates a GitHub Release with `omega-ratrace-<version>.html` and `SHA256SUMS` attached (release notes are generated by GitHub). Before tagging, bump `version` in `package.json` and add a section to `CHANGELOG.md`.
